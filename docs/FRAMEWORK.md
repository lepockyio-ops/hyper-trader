# hyper-trader 框架说明（Hyperliquid 永续 · 策略留空）

## 框架与策略的分工

| 由框架完成（所有策略共用，策略不能绕过） | 由策略插件完成 |
| --- | --- |
| 数据：Hyperliquid 行情、OKX 参考价、录制与核对 | 日线层：这个标的今天能不能做（`context`） |
| 风控：单笔风险、总风险、相关性合并、强平距离、杠杆上限、事件窗口、日/周故障保护、连亏暂停、熔断与暂停 | 信号层：入场单挂、改、撤（`step`），给出触发价与绝对止损价 |
| 止损护栏：距离必须在 `stop_min_pct`–`stop_max_pct` | 分批止盈（`take_profit_legs`） |
| 执行：入场与止损成组下单、对账、止损改量、分批止盈单、看门狗、确定性订单编号 | 日线收盘离场或减仓（`on_daily_close`） |
| 最长持有天数、影子模式、回放回测（与实盘同一代码）、研究矩阵、机器学习门控 | 可选：额外的机器学习特征（`ml_features`） |
| 监控告警、官方事件日历、复盘指标、OpenClaw 运维 | |

## 一个 15 分钟周期里发生什么

1. 对账：交易所持仓与本地状态一致，止损单在场。
2. 管理持仓：影子模式模拟止损与止盈；新的一天先检查最长持有，再调用 `on_daily_close`。
3. 调用 `contexts()` 得到各标的日线结论。
4. 对每个没有持仓的标的调用 `step()`；拿到入场意图后，框架依次做：止损护栏 → 相关性与总风险 → 仓位与杠杆 → 市场检查（资金费、价差、深度）→ 下单或改单。
5. 入场成交后：确认止损在场（否则立即平仓），按 `take_profit_legs()` 挂只减仓止盈单。
6. 写日志与状态。

## 接入策略

见 `docs/STRATEGY_TEMPLATE.md`（先写规格）与 `s03/strategies/template.py`（再写代码）。
默认插件是空白模板 `BlankStrategy`：框架可以完整运行（影子模式、告警、复盘、OpenClaw），但不会产生任何入场；
交易主循环启动时会写一条 `strategy_not_configured` 告警。

## 研究前端（v2.2：找想法 → 筛因子 → 回测 → 统计检验）

`fwresearch/`（两个模板共用）提供想法登记簿、内置因子库（55 个）与因子检验（5 个币时默认跨币种比较）、逐笔 R 的统计检验（Bootstrap、符号翻转、滚动分段、
Deflated Sharpe、PBO）。找想法可选接入 Vibe-Trading，经 `mcp-guard` 白名单代理，只给研究 agent 用，交易类工具一律拒绝。
入口：`python3 scripts/run.py lab …`；详见 `docs/RESEARCH_LAB.md`。

## 上线顺序（与策略无关）

登记想法 → 筛因子 → 研究矩阵回测 → 统计检验（`lab matrix`）→ G0–G6 → 影子模式 → 测试网必测 5 项 → 测试网 live ≥ 4 周（G8）→ 你手动解锁主网、小额实盘（G9）。
