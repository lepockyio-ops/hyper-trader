## 10. 验证门槛（框架统一，不因策略降低）

想法来源与证据链记在想法登记簿（`research/ideas.jsonl`），本规格须写明对应的想法 id；统计检验口径见 `docs/RESEARCH_LAB.md`。


| 门槛 | 要求 |
| --- | --- |
| G0 | 前视偏差检查通过 |
| G1 | 组合回测（主证据）≥ 100 笔；30–99 笔最多判“证据不足”，< 30 笔不做检验；期望 R 的 Bootstrap 95% 区间下限 > 0、按周汇总的 Bootstrap 下限 > 0。上线判定用 `verdict --idea <id>`（示例值） |
| G2 | 最后约 30% 时间段不参与调参：回测**之前**用 `lab idea holdout --id <id> --start <日期>` 登记（只能登记一次）；按入场时间归属，跨边界持仓不算；样本外期望 R > 0 且 ≥ 10 笔、占时间跨度 ≥ 20%；未登记 → 证据不足 |
| G3 | 分段一致性：至少 60% 的时间段期望 R > 0。注意这是同一批结果按时间切段，不是“训练 → 冻结 → 测试”的滚动验证；后者需按段分别选参、冻结、测试（框架未自动化） |
| G4 | 参数稳健（见上）；按尝试次数折扣后 Deflated Sharpe > 0.95、PBO < 0.5（`lab matrix`，示例值；尝试次数如实登记，只登记 1 种时退化为 PSR） |
| G5 | 策略声明的全部必需压力方案（见下方“研究要求”）期望 R 仍 > 0；没跑或失败 → 证据不足；零交易 → 不通过。未实现的情景（见 `docs/RESEARCH_LAB.md`）要在结论里写明 |
| G6 | 极端情景（历史最大单日跌幅、跳空穿过止损） |
| G7 | 代码一致性：模拟运行信号与回测逐条一致 |
| G8 | 模拟运行 ≥ 4 周且 ≥ 20 笔 |
| G9 | 小额实盘（≤ 1,000 USD）≥ 8 周，须你书面授权 |

**研究要求（随策略而定）**：在策略插件里声明 `research_stress`（可选 `cost2x`、`funding2x`；默认两项都要），写明理由。

## 12. 写进代码（Hyperliquid 原生版）

| 规格章节 | 代码位置（`s03/strategy/api.py` 的 StrategyPlugin） |
| --- | --- |
| 1 标的、周期 | settings.toml `[strategy] coins`；信号周期目前为 15 分钟 |
| 3 市场状态筛选 | `context()`（或需要跨标的条件时 `contexts()`）→ `Context(eligible, checks, data)` |
| 4 入场信号 | `step()` → `EntryIntent("place" / "modify" / "cancel", trigger_px, limit_px, stop_px)`；入场方式 `[strategy] entry_impl` |
| 5 止损 | `step()` 给出 `stop_px`；护栏 `[strategy] stop_min_pct / stop_max_pct / stop_min_mode` |
| 6 仓位与风险 | settings.toml `[risk]`、`[cost]` |
| 7 止盈与离场 | `take_profit_legs()`、`on_daily_close()`；最长持有 `[strategy] max_hold_days` |
| 9 参数表 | settings.toml `[strategy.params]`，代码中用 `self.p("名字", 默认值)` |
